# Architecture Decision Records

| ADR                                                                                | Title                                                                          | Status     | Summary                                                                                                                                                                                                                                                                                                                                                                                    |
| ---------------------------------------------------------------------------------- | ------------------------------------------------------------------------------ | ---------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| [0001](0001-hybrid-orchestrator-runtime.md)                                        | Hybrid orchestrator with deterministic runtime                                 | superseded | Replaces the fixed worker-first review loop with an LLM orchestrator that selects actions executed by a deterministic runtime. Superseded by ADR 0019, which restates it.                                                                                                                                                                                                                  |
| [0002](0002-harness-neutral-orchestrator-instructions.md)                          | Harness-neutral orchestrator instructions with thin entry points               | accepted   | One instruction file defines the interactive orchestrator role and thin harness entry points.                                                                                                                                                                                                                                                                                              |
| [0003](0003-copilot-session-entrypoint-and-parent-guard.md)                        | GitHub Copilot CLI session entry point and parent guard                        | superseded | The Copilot launcher and repository hook pass and enforce the parent session id. Superseded by ADR 0005.                                                                                                                                                                                                                                                                                   |
| [0004](0004-scoped-npm-distribution.md)                                            | Distribute the CLI as a scoped public npm package                              | superseded | Publish `@andromarces/agent-loops` with a provenance release workflow and a portable prepare guard. Superseded by ADR 0022, which restates it.                                                                                                                                                                                                                                             |
| [0005](0005-user-scope-integrations.md)                                            | User-scope harness integrations only                                           | accepted   | `agent-loop install` sets up every entry point and guard at user scope; after #139, no agent-loop integration stays at workspace level.                                                                                                                                                                                                                                                    |
| [0006](0006-require-parent-session-for-interactive-runs.md)                        | Require a parent session id for interactive runs                               | accepted   | Every `agent-loop role` init requires `--parent-session` and rejects an unexpanded placeholder; the headless command is the explicit unguarded path.                                                                                                                                                                                                                                       |
| [0007](0007-concurrent-session-runs.md)                                            | Concurrent role runs from one parent session                                   | accepted   | Init registers one session entry per run keyed by work tree; the guard denies while any entry is non-terminal and the reader unions the legacy single-path index.                                                                                                                                                                                                                          |
| [0008](0008-state-file-turn-history.md)                                            | Keep the turn history in the state file                                        | accepted   | Every dispatch appends one fixed-shape `turns` entry (role, status, verdict, head, at) to the state file; one entry per charged step bounds it at `maxSteps`.                                                                                                                                                                                                                              |
| [0009](0009-declare-a-pr-input-on-every-run.md)                                    | Declare a PR input on every run that is PR work                                | accepted   | `--pr <pr>` declares the run PR work on both paths, so that run must end through the `--require-ci <pr>` gate for the same PR and cannot record `unresolvedCompare`. The no-required-check ceiling its Consequences recorded is lifted by ADR 0012.                                                                                                                                        |
| [0010](0010-runtime-owned-required-check-wait-bound.md)                            | A runtime-owned bound on the interactive required-check wait                   | accepted   | `agent-loop role wait-checks` polls the required checks inside a stated bound and returns their states with a `timedOut` flag, because a shell `timeout` does not exist on both supported platforms.                                                                                                                                                                                       |
| [0011](0011-supply-the-required-check-status-to-the-reviewer.md)                   | Supply the required-check status to the reviewer from the runtime              | superseded | A declared-PR run reads the required-check status before each reviewer turn and supplies it in the prompt; the reviewer's own read stays the fallback.                                                                                                                                                                                                                                     |
| [0012](0012-establish-the-absence-of-a-required-check.md)                          | Establish an absent required check from an allowlisted reply                   | accepted   | Each required-check source is classified absent, contexts, or unknown by an allowlist, so only one exact reply per source proves an absence; every other reply, and a merge state the gate cannot read, keeps the refusal.                                                                                                                                                                 |
| [0013](0013-bound-the-headless-required-check-wait.md)                             | Bound the headless required-check wait with the runtime wait                   | accepted   | The headless orchestrator runs `role wait-checks` with a `--timeout` derived from the turn `--timeout`, and reads `timedOut: true` as a pending check, not a pass.                                                                                                                                                                                                                         |
| [0014](0014-extend-the-step-budget-of-a-live-run.md)                               | Extend the step budget of a live interactive run                               | accepted   | `agent-loop role extend --parent-session <id> --max-steps N` raises `maxSteps` in place on a non-terminal run, keeping role sessions, and records each change in `budgetChanges`.                                                                                                                                                                                                          |
| [0015](0015-continue-a-headless-run-from-its-transcript.md)                        | Continue a headless run from its transcript                                    | superseded | `--continue-from <transcript>` resumed the earlier role sessions with a new budget and reset the gate state. Superseded by ADR 0023, which restores the gate state on an unchanged work tree.                                                                                                                                                                                              |
| [0016](0016-resume-a-failed-first-turn-with-a-fallback.md)                         | Resume the session of a failed first turn, with a fallback                     | superseded | A failed first turn keeps the session id its output printed, and a Claude first turn pre-assigns its id; a resume the CLI reports as missing clears the id and reruns the turn once as a first turn inside the same step. Superseded by ADR 0027.                                                                                                                                          |
| [0017](0017-run-a-test-command-before-each-reviewer-turn.md)                       | Run an operator test command before each reviewer turn                         | accepted   | `--test-cmd` runs in the runtime before each reviewer turn, bounded and killed through its own process group or tree (an orphan that left it can survive), and supplies the exit code and an output tail as advisory untrusted evidence, with work tree changes reported; secret-named environment values are redacted from the tail, the command text, and every error text and log line. |
| [0018](0018-copy-local-files-into-a-linked-run-work-tree.md)                       | Copy untracked local files into a linked run work tree                         | accepted   | At init, a linked `--cwd` receives each untracked file of the main work tree that `--cwd` ignores, without overwrite, symlink, work tree, or content in any output; `--no-copy-local-files` opts out.                                                                                                                                                                                      |
| [0019](0019-opt-in-workspace-write-sandbox-for-the-codex-reviewer.md)              | Opt in to a workspace-write sandbox for the Codex reviewer                     | accepted   | `--reviewer-workspace-write` runs a Codex reviewer turn in `workspace-write` with shell network off, keeps the orchestrator read-only and the mutation check on, and records five accepted gaps, since enforcement for that turn becomes detective. Supersedes ADR 0001 and restates its live decisions.                                                                                   |
| [0020](0020-remove-orphan-claim-files-with-a-writer-liveness-check.md)             | Remove orphan claim files with a writer liveness check                         | accepted   | Each lock acquisition removes claim files whose pid is dead or whose unwritten file has no live marker and is past a grace window; a per-process-token marker in the creator's temp name protects a running writer at any age.                                                                                                                                                             |
| [0021](0021-no-parent-session-takeover.md)                                         | Do not let a new session take over a run                                       | accepted   | No takeover command: no check stops a child that read the stored id from releasing the guard. A resumed run from another session stays unguarded; abort and re-init to guard it.                                                                                                                                                                                                           |
| [0022](0022-vite-plus-toolchain-and-npm-distribution.md)                           | Run the dev toolchain and Git hooks through Vite+                              | accepted   | `vite-plus@1.0.0` replaces `oxfmt`, `oxlint`, `vitest`, `lint-staged`, and `husky`; the `prepare` guard installs the Vite+ hook dispatcher, hooks keep format-only `pre-commit` and the `pre-push` gate, and `engines.node` follows the `vite-plus` range. Supersedes ADR 0004 and restates its live decisions.                                                                            |
| [0023](0023-restore-the-headless-gate-state-on-a-continued-run.md)                 | Restore the headless gate state on a continued run                             | superseded | `--continue-from` derives the gate state from the earlier result events, validates it strictly, and restores it only when the current work tree has the head and digest of the last reviewed state. Supersedes ADR 0015. Superseded by ADR 0026.                                                                                                                                           |
| [0024](0024-supply-the-required-check-status-for-a-named-pr.md)                    | Supply the required-check status to the reviewer for every run that names a PR | accepted   | Supersedes ADR 0011 and narrows ADR 0013 decision 6. A run that names a PR with `--pr`, or a headless `--require-ci <pr>`, reads the required-check status before each reviewer turn and supplies it in the prompt; the reviewer's own read stays the fallback.                                                                                                                            |
| [0025](0025-lock-the-install-manifest-beside-the-home.md)                          | Lock the install manifest beside the install home                              | accepted   | `install` and `uninstall` lock `<home>/.agent-loops.lock`, keyed by location, so processes with different `TMPDIR`/`TEMP` contend on one lock; reverses the #193 preference to keep the home free of lock files.                                                                                                                                                                           |
| [0026](0026-detect-a-changed-resolved-model-on-continue-from.md)                   | Detect a changed resolved model on --continue-from                             | accepted   | Supersedes ADR 0023. Claude (the `init` event model) and Copilot report the resolved model, which the transcript records per role. `--continue-from` probes it once per recorded role, under the mutation check and SIGINT cancel of a child turn, and refuses a change. Codex, agy, and opencode report none and stay unchecked; a record with no model warns that the check did not run. |
| [0027](0027-save-the-session-id-of-an-in-tree-transcript-outside-the-work-tree.md) | Save the session id of an in-tree transcript outside the work tree             | accepted   | Supersedes ADR 0016. A headless run whose `--transcript` is inside the work tree writes the pre-spawn session record of an orchestrator or reviewer turn to a file outside the tree. `--continue-from` uses it only when it binds to the transcript state, the work tree, and the run, and the ownership check always runs. The mutation check gets no exemption.                          |
