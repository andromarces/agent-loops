# Architecture and supported agents

Run a task loop across several CLI coding agents using a hybrid orchestrator model.

```text
               +-------------------------------------------------+
               |                  Orchestrator                   |
               | (decides next action: worker, reviewer, finish) |
               +-------------------------------------------------+
                                       ^
                                       | action / result
                                       v
               +-------------------------------------------------+
               |              Deterministic Runtime              |
               | (enforces step budget, timeout, read-only check)|
               +-------------------------------------------------+
                               /                 \
                              /                   \
                             v                     v
                 +-------------------+     +-------------------+
                 |      Worker       |     |     Reviewer      |
                 | (modifies / tests)|     |    (read-only)    |
                 +-------------------+     +-------------------+
```

An LLM orchestrator directs the task by choosing discrete structured actions, while a deterministic Node.js runtime enforces safety invariants, step budgets, process lifecycles, and mutation boundaries.

## Architecture

- **Orchestrator**: Evaluates task status, worker findings, or reviewer feedback, and returns a validated JSON action (`run_worker`, `run_reviewer`, `finish`, `abort`). It does not edit files or execute subshells directly. An interactive parent copies an accepted target back after `finish` when that target sits outside any Git repository. On a run that ends with `--require-ci` or `--compare-head`, a pull request check status read is the only command the exception covers: `agent-loop role wait-checks`.
- **Worker**: Executes the task, modifies files, and runs validation commands in the target repository.
- **Reviewer**: Evaluates the repository state and tests. It must not change a tracked file, an unignored untracked file (a cache included), or Git state; writes only to ignored paths or temporary files outside the repository are allowed. Its CLI runs read-only, except a Codex reviewer, which runs with no sandbox by default and can opt in to `read-only` or `workspace-write`. The mutation check wraps every reviewer turn.
- **Deterministic runtime**:
  - Enforces step limits (`--max-steps`, default 20) and timeout boundaries.
  - Spawns agents, manages persistent sessions, and captures process signals (`Ctrl+C` exits 130).
  - Enforces non-mutating safety on reviewer and orchestrator turns using CLI flags (except for a Codex reviewer with no sandbox) and pre/post Git work-tree mutation detection.
  - Recovers from malformed JSON via a single repair turn.
  - Recovers from a null child closing block via one in-session repair turn inside the charged step (issue #1615, [ADR 0094](https://github.com/andromarces/agent-loops/blob/main/adr/0094-repair-a-null-child-closing-block.md)).
  - Enforces the completion rule with `--require-accept`: after a worker turn, a `finish` needs a later reviewer `verdict: accept` with a `Checks` line on that state; with no worker turn, it needs at least one reviewer report. A `--mode review-only` run refuses the flag and applies the reviewer turn with no flag of its own: the interactive path reaches it because its init dispatch is the reviewer turn, and the headless path refuses a finish until a reviewer turn has run, whatever that turn returned. The gate is on that dispatched turn, not on a report, an accept, or a readable verdict. The gate follows turn order only, so an edit made outside the loop after the accept is not detected.
  - Resolves the PR head in the runtime with `--require-ci <pr>`, the same gate the interactive `role finish` uses, so a headless PR run no longer depends on the parent reporting the compare. It refuses a finish that also sets `unresolvedCompare`, and it reads the reviewed state of the last reviewer turn, so a worker turn after that review refuses the finish.
  - Declares a run PR-shaped with `--pr <pr>`, so a run that states its PR can only end through the `--require-ci <pr>` gate for that same PR. A finish with no gate is refused, and a finish that sets `unresolvedCompare` is refused with it. `--pr <n>` with `--require-ci <m>` for another pull request is a usage error at parse time, because both flags arrive on one command line, so that run never starts. The gate flag is a run input, so no turn supplies it and the refusal ends the run. A base branch with no required check does not refuse the declaration when every required-check source stated that it holds none: the gate passes on the PR head, the clean reviewed tree, and the merge state, and records it (issue #302, issue #336).
  - Runs an optional `--test-cmd <command>` before each reviewer turn, in the runtime and outside the reviewer sandbox, so a reviewer in a sandboxed mode holds test evidence it may not be able to produce: the exit code and an output tail go to the reviewer prompt as advisory, untrusted evidence. See [ADR 0017](https://github.com/andromarces/agent-loops/blob/main/adr/0017-run-a-test-command-before-each-reviewer-turn.md).
  - Runs a Codex reviewer turn with no sandbox by default (`sandbox_mode="danger-full-access"` with `features.apps=false`, [ADR 0038](https://github.com/andromarces/agent-loops/blob/main/adr/0038-run-the-codex-reviewer-with-no-sandbox-by-default.md)), so the reviewer can run the test suite and `gh pr checks`. `--reviewer-sandbox read-only` or `workspace-write` (alias `--reviewer-workspace-write`) selects a sandbox instead. In the sandboxed modes the shell commands that the sandbox runs have network off, and a user Codex execpolicy rule that allows `bash -c`, `sh -c`, or `zsh -c` is an exception, as [ADR 0019](https://github.com/andromarces/agent-loops/blob/main/adr/0019-opt-in-workspace-write-sandbox-for-the-codex-reviewer.md) states. The orchestrator stays read-only in every mode. With no sandbox, the mutation check is the only edit guard, and it detects a change instead of preventing it.
    - It does not see a write outside the repository or a remote write. The mode is recorded at init and kept by `--continue-from`.
  - Pins `AGENT_LOOP_RUNS_ROOT`, `AGENT_LOOP_TEST_SLOTS_ROOT`, and `AGENT_LOOP_SESSION_RECORDS_ROOT` to the paths that it resolves for every worker and reviewer spawn, unless the user set them ([ADR 0049](https://github.com/andromarces/agent-loops/blob/main/adr/0049-pin-the-machine-wide-roots-for-every-child-turn.md)), so a `TMP` override in a turn cannot move the test-slot directory. Sets `npm_config_logs_max=0` for the same spawns, unless the user set `npm_config_logs_dir` or `npm_config_logs_max`, so npm leaves no debug log in its cache ([ADR 0049](https://github.com/andromarces/agent-loops/blob/main/adr/0049-pin-the-machine-wide-roots-for-every-child-turn.md)). Sets `pnpm_config_verify_deps_before_run=warn` for every worker and reviewer spawn, replacing any inherited value (issues #1145, #1385). It stops pnpm from installing from its dependency check before `pnpm run` or `pnpm exec`.
  - Runs each turn of every adapter with a private temporary directory ([ADR 0047](https://github.com/andromarces/agent-loops/blob/main/adr/0047-give-each-codex-turn-a-private-temporary-directory.md), [ADR 0068](https://github.com/andromarces/agent-loops/blob/main/adr/0068-give-the-turn-of-every-adapter-a-private-temporary-directory.md)), because the Codex CLI leaves two empty `.tmp*` directories in its own on every turn, and the scratch files of any other CLI would reach the report of a concurrent reviewer. A `CLAUDE_CODE_TMPDIR` value that the user set stays, so the internal temporary files of Claude Code can still land outside the private directory. The runtime creates the directory with a short `al-` name under the inherited temporary directory and sets `TMPDIR`, `TEMP`, and `TMP` to it. It also lists the inherited directories in `AGENT_LOOP_INHERITED_TMPDIR`, as a JSON array of absolute paths that the parent resolves. A role dispatch records the directory in `lastDispatch.turnTmpdir` before the CLI starts, and the child pid after it starts. A failed write of that record starts no CLI and removes the directory and clears the record from the state, and the turn ends as an error result like any other failed turn.
    - The call that marks a dead dispatch `interrupted` removes the directory with the same identity check, only when the record names the inherited temporary directory of that call, and keeps it with a warning while a process of the dead turn may still run, which on POSIX includes any live member of the process group of the dead child ([ADR 0063](https://github.com/andromarces/agent-loops/blob/main/adr/0063-close-the-limits-of-the-abandoned-turn-directory-removal-that-the-process-group-and-the-record-origin-cover.md), [ADR 0058](https://github.com/andromarces/agent-loops/blob/main/adr/0058-remove-the-turn-directory-of-a-dispatch-that-died-mid-turn.md)).
    - A Codex shell command runs in its own process group ([ADR 0063](https://github.com/andromarces/agent-loops/blob/main/adr/0063-close-the-limits-of-the-abandoned-turn-directory-removal-that-the-process-group-and-the-record-origin-cover.md)). The group check of the dead CLI does not see that descendant (codex-cli 0.166.0 on macOS).
    - A later call on an interrupted run re-checks the kept directory and removes it once no process of the turn runs (issue #1329).
  - Removes the turn directory with a helper process that acts only on the directory with the recorded device and inode. The helper ends at a 30-second bound. A replacement loses at most an empty directory, and a refused, failed, or killed removal only warns. A value of `AGENT_LOOP_INHERITED_TMPDIR` that is present but not a valid list makes the installer refuse every root. The device and inode check is not verified on Windows (#709).
  - Bounds the wait on each child that `exec` and `execBounded` start (issue #1302). A pipe of an exited child that stays open and idle for three seconds is held by another process. The runtime then sends SIGKILL to the process group of the child on POSIX and ends its read of the pipe. Output that the child wrote stays in the result, and a pipe that a slow reader has not drained is never cut. Ten seconds after a timeout or cancel, the runtime stops waiting for a child that did not exit. The turn then ends as timed out or canceled.
    - A descendant that left the process group, or a Windows descendant of an exited child, survives both bounds. A pipe behind an execa transform has no bound.
  - Records validated orchestrator actions, a `refusal` event for each finish a `--require-accept` or `--require-ci` gate refused and for each `run_worker` action a `--mode review-only` run refused, an `unresolved-compare` event for each finish that reports an unresolved PR-head compare, a `head-compare` event for each finish that the `--compare-head` input verified, a `no-required-checks` event for each finish the `--require-ci` gate passed on a base branch with no required check, child results, one `invocation` event per CLI call with usage when the adapter exposes it, timestamps, exit code, and error when `--transcript` is provided. Raw orchestrator responses are not recorded.

See [Architecture Decision Records](https://github.com/andromarces/agent-loops/blob/main/adr/README.md) for background and architectural decisions ([ADR 0001](https://github.com/andromarces/agent-loops/blob/main/adr/0001-hybrid-orchestrator-runtime.md), which [ADR 0019](https://github.com/andromarces/agent-loops/blob/main/adr/0019-opt-in-workspace-write-sandbox-for-the-codex-reviewer.md) supersedes, and [ADR 0038](https://github.com/andromarces/agent-loops/blob/main/adr/0038-run-the-codex-reviewer-with-no-sandbox-by-default.md), which partially supersedes ADR 0019, and [ADR 0002](https://github.com/andromarces/agent-loops/blob/main/adr/0002-harness-neutral-orchestrator-instructions.md)).

## Batch supervisor

`agent-loop batch start` is one foreground supervisor for an explicit set of issues. It creates a linked work tree and branch per issue, runs `--setup-cmd` once in each, and then launches one headless child `node <cli> --cwd <work tree>` per issue, at most `--loops` live. The child is the same headless runtime, so the review gate, the required-check gate, and the test slot are unchanged. The supervisor records local claims in `<runs root>/batches/claims/` and one checkpoint per loop under `<runs root>/batches/<batch id>/`, resumes an interrupted batch with the remaining step budget, reconciles an uncertain GitHub state before a repeat, and removes only a work tree whose push is proved. It creates no label, comment, issue edit, or pull request. [ADR 0106](https://github.com/andromarces/agent-loops/blob/main/adr/0106-foreground-batch-scheduling.md) is the design.

`agent-loop batch audit start` is one foreground supervisor for reviewer audits. It resolves one revision, creates one read-only work tree at that revision, and runs two or more independent reviewer turns under the reviewer mutation check. After every requested audit succeeds, or after the owner approves the partial results, one consolidation worker merges the findings against the open and closed issues that the runtime read. The runtime validates the consolidation and performs every issue write: it links an existing issue or creates one issue per finding. A failed audit, read, consolidation, or creation pauses the audit and creates no issue. The store is `<runs root>/batches/audits/<audit id>.json`, and the created issue set is frozen after creation. [ADR 0109](https://github.com/andromarces/agent-loops/blob/main/adr/0109-coordinate-reviewer-audits-and-consolidated-issue-creation.md) is the design.

A `needs-owner` loop becomes a pending decision and releases its slot once no recorded child process is live. A blocked issue waits on a monotonic poll and launches after its blockers close. `agent-loop batch answer` binds one option to one decision through an exclusive file. A pending decision and a merge wait survive `batch resume`. The supervisor sends bounded desktop notifications on macOS and Windows. [adr/0110-release-batch-slots-on-owner-decisions.md](https://github.com/andromarces/agent-loops/blob/main/adr/0110-release-batch-slots-on-owner-decisions.md) is the design of those parts.

An exit 4 loop becomes a pending decision with reason `pr-head-unresolved`. Its status names the pull request and the next action. [adr/0114-report-an-exit-4-loop-as-needs-owner.md](https://github.com/andromarces/agent-loops/blob/main/adr/0114-report-an-exit-4-loop-as-needs-owner.md) is the design of that part.

## Supported agents

The controller supports these CLI names:

- Claude Code: `claude`
- Codex CLI: `codex`
- Antigravity CLI: `agy` (alias: `antigravity`)
- OpenCode: `opencode` (OpenCode v2, npm `@opencode/cli`)
- GitHub Copilot CLI: `copilot`

Each adapter manages its own persistent session across turns. Model and effort arguments pass through to the CLI on every turn.

A Codex turn can end on a model capacity reply (issue #1012). When the last `error` or `turn.failed` event of the failed turn carries the message `Selected model is at capacity. Please try a different model.`, and the turn did not time out, get canceled, or end on a signal, the Codex adapter marks the error, and the `role dispatch` error envelope adds `"transient": "capacity"`. The headless result prompt that the orchestrator receives carries the same field. An error with another cause carries no field, and so does a turn whose last parsed `error` or `turn.failed` event carries another message. Consecutive capacity failures stay marked. Parsing has a limit: a malformed or truncated final line is ignored, so an earlier capacity event stays decisive then.

The turn still charges its step, because the charge comes before the child starts (ADR 0017) and a refund would add a second state path. The runtime does not retry the turn: the parent chooses the wait and the retry, and a retry inside the dispatch would hide a provider outage from the parent. Not verified: other Codex capacity wordings and a Codex rate limit reply.

A Codex turn can end on a model refusal (issue #1565). When the last `error` or `turn.failed` event of the failed turn carries `The '<model>' model is not supported`, and the turn did not time out, get canceled, or end on a signal, the Codex adapter sets `refusedModel` to that model id. The `role dispatch` error envelope adds `"refusedModel": "<model>"` beside the error text, which still names the refusal. On a `role dispatch` run, a first turn of the role that ends this way charges no step and still records its `turns` entry, so a later refusal charges one. The refund needs the `turnsComplete` mark that init writes; a state written before the mark existed never refunds, now or after a later write. Every other first-turn failure, and a refusal on a later turn, charges a step as before. Init reads no Codex config or model cache (ADR 0084). Not verified: another Codex refusal wording.

A failed Codex turn reports a bounded error: the exit cause, the last `error` or `turn.failed` message, and the stdout and stderr byte counts. The failure detail is bounded to 500 characters, including any ellipsis. The error holds no stream content, so command output such as `aggregated_output` never reaches the envelope or the state file. The capacity classification still reads the full event stream.

Claude Code and OpenCode set the same field (issue #1017). Claude Code 2.1.316 writes `api_error_status: 529` and `is_error: true` on the `result` event of a provider overload. A probe against a local 529 server captured that event, and its text begins `API Error: Repeated 529 Overloaded errors.`. The text carries an environment suffix, so the Claude Code adapter matches the structured status on its last `result` event. A truncated tail keeps an earlier one.

OpenCode sets the field on two signals (issues #1017, #1614). v0.0.0-dev-466 streams a `provider.internal` error whose `status` is the provider HTTP status. A 503 reports a generic service failure, so only 529 is marked. v0.0.0-dev-973 streams a provider overload as a `provider.rate-limit` error whose `status` is 429 and whose structured `response.body` carries the provider error code `overloaded`. A probe against a local 429 server captured that event. A quota reply is a `provider.quota` error, and a plain rate limit carries another code, so neither is marked. The OpenCode adapter matches those fields on its last `error` event, and a truncated tail keeps an earlier one.

Copilot CLI 1.0.106-2 writes the provider HTTP status on a `session.error` event of the JSON output. A probe against a local 529 server with a BYOK provider captured that event. A 503 and a 401 carry that status in the same field. The Copilot adapter marks a `session.error` event with `statusCode` 529, and a truncated tail keeps an earlier event. A retried `model.call_failure` event never decides, so only the terminal failure counts. No live provider reply confirmed the status.

agy 1.4.12 writes one machine line to stderr for a failed turn: `AGY_ERROR: {...}`. Its `short_error` field opens with the provider status and code, and a probe against a local 529 server captured `UNAVAILABLE (code 529): ...`. The agy adapter marks the last complete `AGY_ERROR` line whose `short_error` opens with code 529. A 503 and a 401 carry their own code, so neither is marked. A truncated line is dropped, so an earlier line stays decisive. No live provider reply confirmed the status.

A Copilot worker turn can be refused a shell command, so it cannot be relied on to run a validation command (issue #713, ADR 0035). The adapter passes `--no-ask-user` and no allow flag, and Copilot answers a shell call with `Permission denied because no interactive user response was available.` Two live worker turns on Copilot CLI 1.0.96-2 (macOS 27.2) were refused `bash <script path> <args>`, and the command did not run. When the assistant text of a worker or reviewer turn holds that denial, the `role dispatch` envelope of the turn adds `"shellDenied": true`, the headless result prompt that the orchestrator receives carries the same field, and the turn stays `ok`.

A turn with no denial text carries no field, so a later turn clears it. An orchestrator turn never carries it. A denial that the text does not repeat is not flagged. The worker prompt tells a worker to name a refused command in `Checks` and `Blockers`. The parent must run the validation itself, or choose another worker CLI, when a task needs a command run. Not verified: a scoped `--allow-tool` flag under the runtime arguments, the Copilot event that reports a denial, and a Windows host.

### Closing block recovery

The parent reads the closing block of the turn. A child can answer a late event after its block, so the last message of the turn can hold no block. Each adapter selects the message that governs:

- A closing block attempt is a report label (`Conclusion`, `Why`, `Blockers`, `Checks`, `Notes`, `Deferred`) or `Verdict`, in any case, anywhere in a message, followed by optional emphasis marks or whitespace and a colon. Any form counts, parsed or not.
- Codex and Copilot: the adapter returns the last message that holds an attempt, alone, and falls back to the last message when none does. A later malformed block wins and surfaces through `raw`, so an earlier accept never overrides it.
- OpenCode: the adapter groups text parts by `part.messageID`, joins the parts of one message unchanged, and starts each other message on its own line. The last closing block governs alone, and the join drops every earlier message with an attempt.
- OpenCode fails the turn with an error, and no accept can come from it, when the order is ambiguous: the position spans of two messages with an attempt overlap, or the unidentified message (every part without a valid, non-empty string `messageID`) governs, yields accept, and spreads its label lines over more than one part. The error holds the redacted text of every message (ADR 0017), cut to its last 4000 code units with a line that states the cut.
- A late bare `Verdict: accept` after a full block gives an unparseable report with verdict `unknown` and no `Checks` line, so the `--require-accept` gate refuses.
- Claude Code and Antigravity CLI return one final result, so the adapter cannot recover the earlier block. A late answer replaces the report of the turn. The worker prompt rule against a background watcher and for a closing block of the whole turn is the only guard.

A child turn whose successful string response parses to a null report takes one repair turn in the same session. The repair asks for the closing block alone in a short canonical format, keeps the original findings, checks, and verdict, and runs inside the charged step. A reviewer repair runs under its own mutation check, so a write is still a mutation, and a cancel that lands with a handled repair failure still ends the turn as a cancel. The repaired block is untrusted: it must keep the normalized content of each original label, an absent label may gain only `none`, and a reviewer verdict must match an explicit original verdict. An accept needs a non-empty original value for every required label and for `Checks`, so an empty original label cannot become acceptance evidence. A lost or replaced session, a failed repair, a repair that still parses to null, and a repair that does not match the original leave the original response in `raw`. A cancel during the repair ends the turn as a cancel on the original error path, with no result and no `raw`. A repair that replaces the conversation keeps the replacement mark, so the next turn delivers the role preamble or task. A report that parses but lacks the reviewer `Checks` or `Verdict` line takes no repair, and `acceptanceFailure` refuses it as before. Per-adapter resume behavior is unverified until the live item in issue #710 records a result ([ADR 0094](https://github.com/andromarces/agent-loops/blob/main/adr/0094-repair-a-null-child-closing-block.md)).

The live checks and the history of this rule are in issues #449, #458, #461, #467, #493, #494, #509, #510, #529, #639, and #710.

Copilot live checks (issues #653 and #708) are in [ADR 0094](https://github.com/andromarces/agent-loops/blob/main/adr/0094-repair-a-null-child-closing-block.md#copilot-closing-block-live-checks). Verified on macOS 27.2 with GitHub Copilot CLI 1.0.106-5. Windows and Linux are not verified.

### OpenCode model default

With `opencode` and no `--<role>-model`, the adapter passes no `--model` argument. OpenCode uses the configured `model` when it is enabled and its provider is available in the project; otherwise it falls back to the newest available supported model. A model already selected for a session takes precedence over the configured default. The resolved model is machine- and project-dependent, so it varies by configuration, authentication, and session history. `opencode session export <id>` names the model that ran.

An explicit `--<role>-model` passes through unchanged, with no variant appended. `--<role>-effort` applies to an explicit model and reaches the CLI as `<model>#<effort>`. An effort without a model is rejected, because the installed CLI accepts a variant only inside `--model provider/model#variant`.

`--<role>-model` and `--<role>-effort` record what the caller requested, not the effective model. For an explicit model, the adapter logs the effective `model#effort` it passes. For an implicit default, the adapter logs that OpenCode selects the model and names none; `opencode session export <id>` records the model that ran, and the adapter records it as `resolvedModel` for `--continue-from` (ADR 0026).
