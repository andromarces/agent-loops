# 0026. Detect a changed resolved model on --continue-from

## Status

accepted

Supersedes [ADR 0023: Restore the headless gate state on a continued run](0023-restore-the-headless-gate-state-on-a-continued-run.md). The decisions of ADR 0023 that still hold are restated below. One changes: the accepted gap about a changed CLI default model closes for the CLIs that report their resolved model.

## Date

2026-10-07

## Context

A headless run that reaches its step limit exits 2 and keeps its work tree, but a new invocation builds every role with `sessionId: null`. The `--transcript` file records each role's final session id (issue #362). ADR 0023 restores the completion gate state on an unchanged work tree (issue #393) and compares the recorded role model and effort exactly. The transcript records the model the caller requested. An omitted model, and an alias such as `opus`, resolve inside the CLI, so a change of that default or alias target between the two runs went undetected, and the continued run resumed a session under another model (issue #394). ADR 0023 recorded this as an accepted gap. This ADR closes the gap for the CLIs whose output names the resolved model, so it supersedes ADR 0023 and restates its decisions.

A probe of the five CLIs on macOS shows which outputs name the resolved model. The first probe covered Claude, Copilot, and the three CLIs below. Issue #567 repeated the probe for the three on 2026-10-08, with a trivial prompt from a scratch directory outside the repository (codex-cli 0.162.0-alpha.18, agy 1.3.1, opencode v0.0.0-dev-20716):

| CLI      | Output that names the model                                              | Used                                  |
| -------- | ------------------------------------------------------------------------ | ------------------------------------- |
| claude   | `model` of the `system` `init` event of `--output-format json --verbose` | yes, one well-formed model            |
| copilot  | `data.model` of each `assistant.message` event of `--output-format json` | yes, when all messages name one model |
| codex    | none in `--json`: the events carry the thread id and usage only          | no                                    |
| agy      | none in `--output-format json` or `stream-json`                          | no                                    |
| opencode | `model` of each `assistant` message of `opencode session export <id>`    | yes, when all streamed messages agree |

The #567 probe found these facts:

- **codex**: `codex exec --json` emitted `thread.started`, `turn.started`, `item.completed`, and `turn.completed`, and no field named a model. The local rollout file `~/.codex/sessions/YYYY/MM/DD/rollout-<time>-<thread id>.jsonl` holds the model in the `payload.model` of its `turn_context` record. No Codex command prints it. The file layout and format are not documented, the home directory comes from `CODEX_HOME`, and the lookup walks dated directories, so the adapter does not read it (alternative 10).
- **agy**: `agy --input-format text --output-format json --mode plan` printed `conversation_id`, `status`, `response`, `duration_seconds`, `num_turns`, and `usage`. `--output-format stream-json` printed `init`, `step_update`, and `result` events, and none names a model. The `--log-file` output has no model name. The model string `gemini-3.8-flash-medium` appears only inside protobuf blobs of the table `gen_metadata` of `~/.gemini/antigravity-cli/conversations/<conversation id>.db`, beside the tool schemas and a `model_enum` placeholder. That is an undocumented binary record, so the adapter does not read it (alternative 11).
- **opencode**: `opencode run --standalone --format json` with no `--model` emitted `step_start` and `text` events, and none names a model. `opencode session export <session id>` printed `{info, messages}`. Its `assistant` message holds `model: {id, providerID}`, and the probe printed `claude-haiku-5-5` from provider `opencode-go`, the CLI default. A resumed turn added new `assistant` messages with the same field.

## Decision

1. `--continue-from <transcript>` reads the session ids from the `roles` of an earlier transcript and gives the run a new `--max-steps` budget.
2. The run is refused before any turn when a role kind, a role's recorded model, a role's recorded effort, or `--cwd` differs from the earlier run. One rule covers every CLI: model and effort compare exactly, so an omitted value matches only an omitted value. The resolved-model check of decisions 8 to 11 adds a refusal for a changed CLI default. A refusal writes no transcript. The transcript write is atomic, so a failed write keeps the earlier file. When `--transcript` names the same file, the rewrite keeps the earlier events and adds a `continued` event with the earlier outcome.
3. A headless run that returns an exit code appends a `gate` event as the last event of its transcript. The event holds the gate state of the run: `workerRan`, `reviewerRan`, `reviewerTurnDispatched`, `acceptedSinceWorker`, and `lastReviewed`. A run that ends on a thrown error (SIGINT, a fatal turn, a detected mutation) appends none.
4. `--continue-from` does not trust that record. It rebuilds the gate state by replaying the transcript events in file order through `applyResult`, the transition function that `runLoop` also applies after each child result: a worker result clears the accept, and a reviewer result sets `reviewerRan` when it ended `ok` and sets or clears the accept from its verdict and Checks line. Every result replaces the reviewed state with its own. A `continued` event restarts the replay at the reset state, and so does a transcript of a continued run that has none. The replay returns no state, which keeps the reset, unless all of these hold:
   - Every event is an object with a string `type`. Every `invocation` event has a role that is exactly `orchestrator`, `worker`, or `reviewer`. Every `result` event has a role that is exactly `worker` or `reviewer`, and the fields of its `ok` or `error` result with the right types (a string `response` or `error`, a reviewed state of strings and booleans when present).
   - No worker or reviewer invocation is left without a result.
   - The last event is the `gate` event.
   - The replayed state equals the `gate` event.
     Any unexpected value resets and never throws.
5. The replayed state restores only when it is well formed and the work tree is unchanged. Well formed means: the head is a Git object name or `unborn`, the digest is a SHA-256 hex string, `clean` is a boolean, and `exact` is true. Unchanged means the current snapshot is exact with the same head and digest. The restored `lastReviewed` is the current runtime state, so `clean` and `exact` never come from the file. Any other case keeps the reset: `runLoop` takes `continued`, which starts `workerRan` true, and every other gate input starts empty, so a finish needs reviewer evidence from the continued run. `finishRefused` is never restored, because it paces refusals and is not completion evidence.
6. The orchestrator prompt states the new budget, and states whether the gate was restored or reset.
7. The interactive design of issue #361 shares nothing with this change. `src/lib/continuation.mjs` takes plain role objects, so a later change can reuse the compatibility check.
8. An adapter that reads a resolved model from its output records the resolution state of each turn that ran in `state.resolvedModel`, for the session the role keeps, as one of three distinct states. **Resolved**: a model id, when the output names exactly one model from well-formed evidence (at least one value, every value a model id, which is a non-empty string with no whitespace or control character, and all values equal). **Unresolved**: `null`, when the output is unreadable, malformed, or ambiguous (several models, no model, a value of another type). An earlier model is replaced by `null`, because it describes an earlier turn and the record must not offer a stale value to compare. **Not reported**: the field is absent, for Codex and agy, which never report a model in a supported output, and for a transcript written before this change. The Claude adapter reads the `model` of the `system` `init` event, which names the main-loop model whatever subagent or helper model ran later. Two `init` events that name different models, or an `init` event with no valid model, are unresolved, and the adapter then never falls back to `modelUsage`. An output with no `init` event reads the keys of `modelUsage`, which must be an object whose entries are objects; more than one key means a subagent or helper model ran too, so the turn is unresolved. The Copilot adapter reads the `model` of every `assistant.message` event that has the field; different models, or a malformed value, are unresolved. The opencode adapter reads no stream event. After a turn that kept its session, it runs `opencode session export <id>` in `--cwd`, with the `--timeout` bound and the run signal, and collects `providerID/id` of the `model` of each `assistant` message whose id a stream event names in `part.messageID`, because the export holds the whole session. A streamed message that the export lacks, a malformed `model`, a stream with no message id, several models, an export that fails, or output that is not a JSON object with a `messages` array are unresolved. A failed opencode turn records `null` and never reads the export. The same three states apply to every turn whose child process ran, failed or not, because a failed turn may have run the session on a model. A failed turn whose output carries well-formed evidence of one model records it. A failed turn with no readable or an ambiguous output records `null`: a non-zero exit with no output, a timeout, a cancel, a signal, an exit 0 whose output does not parse, and a turn that fails a later session check. The record is set before those checks, so none keeps a stale model. The evidence counts only when the output's session is the session the role keeps after the turn: the retained id, or the new id that a first turn adopts. An output that reports another session than the retained one (the case `resumeMismatchError` catches), or no valid session, cannot be tied to the kept session, which may have run on any model, so the record is `null`. The session and the model come from one source: for Claude, the output must name exactly one valid session across all its events, and every result event, and every `init` event, must name that session itself; for Copilot, whose assistant messages name no session, every event that carries a session id must name the same one, and the last result event, from which the session is read, must name it. Output that names more than one session, a malformed session, or a result event with no session records `null`. Otherwise a continuation would refuse the model A of the kept session on the strength of the model B of another session, and accept B. A missing-session resume that reruns as a first turn records both turns in order, so the rerun decides, and a rerun that fails records `null`. The record stays unchanged only when no child process ran at all (`exec` reports a spawn failure: no exit code, and no timeout, cancel, or signal). The role objects hold the field, so the transcript `roles` record it.
9. `restoreSessions` copies a recorded model id or `null` to the new role, so a role that does not run in the continued run keeps the state for the next continuation. An absent or malformed value stays not reported.
10. After `restoreSessions` and before any turn, `verifyResolvedModels` runs one read-only probe turn per role whose latest recorded state is resolved, through `runProbeTurn`. The probe uses the role kind, model, and effort of the new run, in a new session, never the continued one, in `--cwd`, with the `--timeout` bound. It runs under the guards of a child turn: the mutation check (a probe that changes the work tree throws `MutationError`, and a failed snapshot throws `SnapshotError`) and the run's SIGINT signal, which cancels the CLI call. Either halts the continuation with no transcript write, exit 1 for a mutation and 130 for a cancel. The run is refused with exit 1 when the probe resolves a model that differs from the recorded one. The message names the role and both models, and states that a new `--<role>-model` value is refused by the flag rule, so the recovery is to restore the earlier CLI default or to start a new run without `--continue-from`.
11. The comparison runs only when both sides are resolved, and never against an older model. A recorded `null` skips the probe and the comparison, and warns that the default-model check did not run because the latest turn of the earlier run did not name one model. A probe result that is `null` or absent skips the comparison with a warning that the probe did not name one model, never a refusal and never a silent pass. Any other probe failure refuses the continuation, because the model is then unverified. A role whose record is not reported is not probed, and the operator is told that the check did not run: a warning for a CLI that can report a model (an earlier version wrote the record), and an info line for a CLI that never reports one.

## Consequences

- A continuation on the tree that the earlier run last reviewed costs no extra reviewer turn. A continuation on a changed tree, or with no derivable gate, costs at most one.
- A continuation never accepts a finish on a saved verdict for a changed tree: the restore needs the same head and digest.
- The transcript gains one event type, `gate`, that holds the final gate state. A transcript from an earlier version has none, so it continues with the reset, as it did before this change.
- **Accepted gap:** the transcript is a local file with no signature. The restore checks that the events are well formed and replay to the recorded state, and that the work tree matches. It does not check any event against another source, and it makes no promise about a deleted, added, or reordered event beyond that replay: an edit resets only when it makes an event invalid or makes the replay differ from the `gate` event. The gap is a forged sequence that is well formed and replays to the recorded state, for example a transcript whose events and `gate` event were all rewritten to end on an accept of the current head and digest. The same trust already covers the session ids in that file.
- A run that ends on a thrown error (for example SIGINT) writes no `gate` event, so its continuation resets, and so does a continuation of a same-file transcript whose later run ended on a thrown error.
- A continuation that restored a gate and ran no turn ends in a state that the replay, which restarts at the reset state, does not reproduce. The next continuation resets. That fails closed.
- A transcript file inside the work tree is an untracked file, so it changes the digest and keeps the reset. Keep it outside the work tree.
- A continuation whose `--transcript` path differs from `--continue-from` holds only its own events, so one that ran no turn has no result to restore from, and the next continuation resets.
- A continuation of a role on Claude or Copilot costs one extra model call per such role. Each call starts a session that the CLI keeps in its own session list.
- **Accepted gap:** a change of a CLI's own default model is not detected for Codex and agy, which report no resolved model in a supported output (the probe of issue #567 found only an undocumented local record for each). Pass an explicit `--<role>-model` in both runs to pin it. An explicit model that is an alias is checked only on Claude, Copilot, and opencode.
- An opencode turn costs one more CLI call, the export, and a continuation of an opencode role costs one probe turn plus its export. `session export` prints the whole session, so a long session enlarges the buffered output. A failed export makes the turn unresolved, never a failed turn.
- **Unverified:** the opencode export format comes from a development build (`v0.0.0-dev-20716`). A format change makes the record `null`, so the check does not run and the operator gets the warning of decision 11.
- Claude Code names the main-loop model on the `system` `init` event of `--output-format json --verbose`, which prints an array of events with the same session id as the result (issue #566, probed on Claude Code 2.1.293 on macOS). A turn that ran a Haiku subagent beside a Sonnet main loop listed both models in `modelUsage` and named only the Sonnet model on `init`, so a multi-model Claude turn resolves. A Claude Code version whose output has no `init` event falls back to the one-key `modelUsage` rule.
- **Accepted gap:** `--output-format json --verbose` prints the events of the turn as one JSON array, which includes the `system` `init` event, so a long turn enlarges the buffered `stdout` and, on a failed turn, the error text that `exec` builds from it. No adapter bound covers this. execa 10.0.1 caps each output stream at `maxBuffer`, 100,000,000 characters of decoded text by default. `exec` ignores the execa `failed` and `isMaxBuffer` fields, so an overflow can go undetected and can cut `stdout`. That defect predates this change and is out of scope. If the cut leaves an incomplete JSON array, parsing fails, and the turn records the model as `null` before the error is rethrown.
- An `init` event counts only when it names the session the role keeps, like the result event. An `init` event with no session, or another session, leaves the turn unresolved.
- **Accepted gap:** a Claude turn whose output has no `init` event and several models in `modelUsage`, a Copilot turn whose messages name different models, and a turn whose evidence is malformed are unresolved. The latest turn governs: a role whose latest turn is unresolved is not checked, even when an earlier turn named a model, and the operator gets the warning of decision 11. The alternative, an older model kept as the baseline, falsely refuses an unchanged model B after an ambiguous turn and passes a B-to-A change against a stale A (alternative 9).
- A transcript written before this change records no `resolvedModel` (not reported), so it continues unchecked, with the warning of decision 11. A turn run after this change always records a model id or `null` for a Claude or Copilot role.
- The probe runs before `assertGitWorkTree`. A `--cwd` that is not a Git work tree fails the probe's snapshot, so the run is refused.
- **Unverified:** the probe ran on macOS with the installed Claude Code, Copilot CLI, and opencode only. A Windows run and other CLI versions are not verified.

## Alternatives

1. **Stored gate flags in the transcript**: rejected after review. An edited flag bypasses a gate. The `gate` event is a record that the replay of the events must reproduce.
2. **Restore with no tree check**: rejected. A saved accept cannot cover an edit made between the runs.
3. **A new session-state file next to the transcript**: rejected. The transcript already holds the ids and the results, and a second file adds a second source of truth.
4. **Compare an effective model per adapter from configuration**: rejected. It needs per-CLI knowledge of configuration layers and of the account default, and cannot resolve an alias.
5. **Compare after the first turn of each role**: rejected. The turn has already resumed the session under the changed model, so the check could only report it.
6. **Record every key of `modelUsage`**: rejected. A helper or subagent model that changes would refuse a continuation that the role model does not need to block.
7. **Record only, with no probe**: rejected. A record that nothing compares does not meet the issue.
8. **Move the Claude adapter to `--output-format stream-json --verbose`**: rejected. The `json` format with `--verbose` already prints the `init` event as an array of events, which `findSessionId` and `findResultEvent` read, so the change is one argv flag and no new parser (issue #566).
9. **Keep the last well-formed model across an unresolved turn**: rejected. The record then describes an older turn than the session state. An unchanged model B after an ambiguous turn is refused against the older A, and a B-to-A change passes against the stale A. Deleting the value is rejected too, because the continuation then cannot tell that the check did not run.
10. **Read the Codex rollout file for `turn_context.model`**: rejected. The file has a model, but its layout and format are not documented and no command prints it. The adapter would depend on `CODEX_HOME`, a directory walk by thread id, and a format that can change. Reopen it when Codex prints the model or documents the file (issue #567).
11. **Read the model string from the agy conversation database**: rejected. The string sits in an undocumented protobuf blob of a local SQLite file, beside a placeholder enum and unrelated model names, and the read needs an SQLite and a protobuf reader. Reopen it when agy prints the model (issue #567).
