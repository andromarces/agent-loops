# Test slot

`agent-loop test-slot` runs one command only while it holds one of N machine-wide test slots. Parallel full-suite runs in different work trees and projects do not oversubscribe the host (ADR 0039).

```bash
agent-loop test-slot --slots 2 --wait 600 -- node node_modules/vite-plus/bin/vp test run
agent-loop test-slot --if-held -- node node_modules/vite-plus/bin/vp test run tests/foo.test.mjs
agent-loop test-slot --if-held -- "pnpm exec vp test run tests/foo.test.mjs"
```

- **Command.** Two or more arguments after `--` form an argument vector, spawned with no shell option, so no shell quoting applies. On Windows the vector must start with a real executable such as `node`, not a `.cmd` or `.bat` shim such as `pnpm`. A shim is outside the no-shell contract: the spawn runs it through `cmd.exe`.
- **Shell-string form.** One argument after `--` keeps the shell-string form. That form is exactly one argument, quoted for the calling shell. It runs through the platform shell (`/bin/sh -c`, or `cmd.exe` on Windows) in the current directory, as `--test-cmd` runs its command. stdout and stderr pass through, and stdin is closed. Log lines go to stderr and never hold the command text.
- **`--slots <n>`.** Slot count. Defaults to 1, on every CPU count (ADR 0046). Env: `AGENT_LOOP_TEST_SLOTS`. A wrapper starts only while fewer than its own N slots are held by live owners, counted under one short lock. Wrappers that pass different N therefore never run more than the largest N among them, and an N=1 wrapper waits until no other holder runs.
- **`--wait <seconds>`.** Longest wait for a slot. Defaults to 1800 (30 minutes). Env: `AGENT_LOOP_TEST_SLOT_WAIT`. The command starts only strictly before the bound: a slot won at or after it is freed unused, and the command does not run. `0` is one attempt: the command runs if a slot is free now, otherwise the wrapper exits 75 at once.
- **`--if-held`.** Runs the command directly, holding no slot and waiting for none, while no slot file is held by a live owner. While any slot is held, the wrapper waits for a slot as without the flag, under the same `--slots`, `--wait`, and exit 75 rules. A missing slot directory and a stale slot count as not held. The check is one read with no lock (ADR 0044). Limit: a command that starts while all slots are free holds no slot, so a slot holder can start beside it.
- **Precedence.** A flag wins over its env, and an env value is read only when its flag is absent. An empty env value counts as unset. An invalid env value is a usage error only when no flag replaces it.
- **Slot directory.** `<os tmpdir>/agent-loops/test-slots`, one lock file per held slot and one short acquisition lock. Env: `AGENT_LOOP_TEST_SLOTS_ROOT`. A slot whose owner process is gone is reclaimed. A slot file that cannot be read or parsed counts as held until the stale rules prove it stale. Where `os.tmpdir()` is shared between OS users, as `/tmp` on Linux, set the env to a directory per user.
- **Nested call.** The command runs with `AGENT_LOOP_TEST_SLOT_HELD` set to its slot file and owner nonce. A wrapper that starts with it set runs its command at once, in the same process group. It does so only while that slot is still held by that live owner. Any other marker, for example one exported by hand, is ignored with a warning, and the wrapper waits for a slot.
- **Signals.** SIGINT or SIGTERM ends the process group (POSIX) or process tree (Windows) of the command, then frees the slot. The outer kill also ends a nested wrapper and its command. A hard kill of the wrapper leaves the slot to the stale-owner recovery and can leave the command running.
- **Runtime and child turns (ADR 0040).** The runtime runs `--test-cmd` inside a slot through the slot module, with the same count, directory, and wait environment variables. Its wait bound is separate from `--test-cmd-timeout`: at the bound the command does not run and `testRun.status` is `slot-timeout`.
  - Every worker and reviewer turn is told to run a targeted test file through this wrapper with `--if-held`. It runs directly while all slots are free. It waits for a slot while any slot is held (ADR 0044, which partially supersedes ADR 0040, and ADR 0099 for the text-reader tier). A full suite runs only through the plain wrapper. Its command names the Node binary and the CLI script of the run, or the run relies on the required CI checks.
  - The targeted run covers the mirror test files first, then the test files that import a changed source file directly. It then covers the test files of direct importers of a changed source file. Next come the test files that name the path or file name of a changed non-module file. Such a file is a script or config file, and the list holds at most 10 files in total.
  - The rule names the argument-vector form as the default from Git Bash on Windows, so the suite command needs no quoting step. It also states that a Windows vector must start with a real executable such as `node`, not a `.cmd` or `.bat` shim. Such a shim is outside the no-shell contract.
  - A run whose paths cannot be quoted in every shell keeps a direct targeted run, and a broader run relies on the required CI checks.
- **Approved limits (ADR 0039).** `agent-loop test-slot --help` names the three limits: the shared slot directory (see Slot directory), detached work, and nested-wrapper signals. On POSIX, a signal sent only to a nested wrapper ends its direct child and can leave grandchildren running. A signal to the outer wrapper ends the whole group. Detached work that a wrapped command starts, for example through `setsid` or a daemon, can outlive the slot release. It runs outside any slot, as with the `--test-cmd` orphan limit (ADR 0017).

| Code         | Meaning                                                                                                                                                                                  |
| ------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| command code | The command ran. A command ended by a signal gives 128 plus the signal number.                                                                                                           |
| 64           | Usage error. The command did not run.                                                                                                                                                    |
| 75           | No slot was won within the wait bound. The command did not run.                                                                                                                          |
| 130, 143     | SIGINT or SIGTERM reached the wrapper, at any nesting level.                                                                                                                             |
| 1            | Any other wrapper failure, such as a slot directory that cannot be written or a failed release of the acquisition lock. The command did not run, and a slot taken in that pass is freed. |
